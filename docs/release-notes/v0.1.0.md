First release of **krotos**, a namespaced Kubernetes operator that rotates database passwords
stored in HashiCorp Vault on a schedule, only inside a change window, and restarts the workloads
that use them.

## Highlights

- **Engines:** PostgreSQL, MySQL, MariaDB, ClickHouse.
- **Vault:** KV v1 and v2; Kubernetes or token authentication.
- **Scheduling:** `cron` or `every: 30d`, a mandatory change window with time zone, days,
  overnight windows and `minRemaining`; manual triggers with `rotate-now` / `ignore-window`.
- **Safe rotations:** the current password is verified before anything changes and the new one
  before it is published; every step is recorded in `status.step` and resumed after a restart;
  repeated failures put the database back on the old password.
- **No plain passwords outside Vault:** in-flight passwords live in Vault (and memory), never in
  Kubernetes objects or logs; PostgreSQL gets a SCRAM verifier, MariaDB a native hash and
  ClickHouse a salted SHA-256, so passwords never reach the database server's logs.
- **Delivery to applications:** Vault Agent / CSI, External Secrets Operator (`force-sync`) or
  Vault Secrets Operator; workloads restart only once the synced Secret holds the new password.
- **Restarts:** Deployments, StatefulSets and DaemonSets, by name or label selector, with rollout
  tracking like `kubectl rollout status`.
- **Observability:** conditions, events and Prometheus metrics, with alert examples in the README.

## Install

```sh
helm install krotos oci://ghcr.io/warewave-technology/charts/krotos --version 0.1.0 \
  --namespace team-a --create-namespace
```

or, with kustomize-built manifests (namespace `krotos-system`):

```sh
kubectl apply -f https://github.com/Warewave-Technology/krotos/releases/download/v0.1.0/install.yaml
```

Image: `ghcr.io/warewave-technology/krotos:0.1.0` (linux/amd64, linux/arm64).

Then set up Vault and create a `VaultConnection` and `DatabaseCredentialRotation`s; the
[README](https://github.com/Warewave-Technology/krotos#readme) walks through every step.

## Known limitations

- Rotations are not zero-downtime: new connections with the old password are refused until
  the workloads have restarted, which is why a change window is mandatory.
- MariaDB: only `mysql_native_password` accounts. ClickHouse: only users managed by SQL.
- The API is `v1alpha1` and may change in incompatible ways before `v1`.
